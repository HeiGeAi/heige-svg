# 公众号 SVG 动图拆解

## 结论：不是 HTML 录屏，是内联 SVG

5 篇文章的正文里没有 GIF，也没有 video。动图是直接写在正文 HTML 里的 `<svg>`，动画用 SVG 自带的 SMIL（`<animate>` 和 `<animateTransform>`）。

这解释了几个现象：放大不糊（矢量）、字清晰、体积小（单张中位 26KB）。

原稿可能是用什么写的无法从成品判断。从高度统一的结构和四位小数的 keyTimes 看，很可能由程序生成，这一点是推断。

## 手法一：严格收窄技术范围

| 项目 | 实测 |
|---|---|
| 出现过的标签 | `svg desc g path rect circle line text tspan image animate animateTransform`，没有别的 |
| 从未出现 | `id`、`clipPath`、`mask`、`defs`、`use`、渐变、滤镜、`style` 标签、`foreignObject`、`animateMotion`、`text-anchor`、`font-family` |
| 被动画的属性 | 只有 `opacity`（1373 次）和 `transform`（288 次） |
| transform 类型 | scale 165、translate 117、rotate 6 |
| 时间写法 | 全部 1661 个动画都是 `begin="0s"`、`repeatCount="indefinite"` |
| 计算模式 | spline 1555、discrete 98、linear 8 |
| 缓动曲线 | 只有 3 条：`0 0 1 1` 4656 段，`0.16 1 0.3 1` 1534 段，`0.42 0 0.58 1` 1212 段 |

第三方开发者实测过草稿接口：微信会剥掉 `id`，所以依赖 id 引用的渐变、clipPath、mask、use 都会失效。这和上表吻合。来源：[mbeditor v5.6.0 发布说明](https://github.com/AAAAAnson/mbeditor/releases/tag/v5.6.0)（第三方记录，非官方文档）。

## 手法二：单一时间轴

一张图里几乎所有动画共用同一个 `dur`，所有时刻都写进 `keyTimes`。这样循环多少遍都不会错位。例外是转圈（0.8–0.9s）和序列帧（约 2.4s），它们独立循环。

## 手法三：静态属性就是兜底帧

去掉所有动画标签后，图片仍然显示完整的完成态（已抽 3 张验证）。这意味着不支持动画的环境下，读者看到的是一张讲得清的静态图。

## 手法四：标题转路径，其余用系统字

- 标题是衬线字转的 `<path>`，坐标取 2 倍后四舍五入成整数，再 `scale(0.5)`，一个标题约 6–13KB
- 正文 `<text>` 不写字体，继承文章字体（实际显示为无衬线）
- 居中靠估算字宽算 x，没有用 `text-anchor`
- 终端里的等宽字也转路径

## 手法五：没有裁切，就绕开裁切

- 手机的下半截伸出画布，靠 viewBox 裁掉
- 进度条用 `scale(0.01 1)` 到 `scale(1 1)`
- 绕点缩放用三层嵌套：外层 translate，中层 scale，内层反向 translate
- 打字机是逐字一个 `<g>`，每字淡入 0.02 秒
- 序列帧是一叠 `<image>`，用 discrete 切换透明度（鲸鱼动画有 51 张）

## 手法六：节奏

| 项目 | 实测 |
|---|---|
| 循环时长 | 中位 8 秒，范围 2.6–12.6 秒 |
| 第一个变化出现 | 中位 0.2 秒 |
| 最后变化到循环结束 | 中位 0.3 秒 |
| 淡入 | 常见 0.02（打字）、0.1–0.15 秒 |
| 退场 | 0.3 秒或 0.6 秒，用 inout |
| 光标移动 | 常见 0.6 秒，inout |
| 点击波纹 | 0.45 秒放大，同时淡出 |
| 单张体积 | 11–70KB，中位 26KB |
| 单张动画数 | 6–132 个，中位 22 个 |

## 手法七：统一的版式

画布 750×720（手机类 750×750），上下结构固定：

- 眉题：21 号灰字，`对象 · 这一节`
- 标题：衬线，一句结论
- 分隔线：y=170，`#D8D0C1`
- 内容区
- 分隔线：y=646
- 脚注：23 号，一个硬信息

背景是一张 750×960、约 64KB 的纸纹 JPG，每篇文章重新上传一次，靠 `<image>` 引用微信图床地址。

配色：纸底不变，内容 UI 跟着被讲的产品走。

| 文章 | 主色 |
|---|---|
| MiniCPM-OCR、Few Shots | 暖黑 `#1E1C19` + 红 `#CF4436` |
| AGI Bar | 深色 `#17161C` + 琥珀 `#FFC434` |
| DSH Go | 深蓝 `#142660` + 蓝 `#4E6FFF` |
| ChatGPT | 黑白 `#0D0D0D` |

## 手法八：图和文字怎么分工

- **图负责「怎么回事」，文字负责「为什么和有什么限制」。** 操作过程、系统协作、对比结果进图。价格、适用人群、注意事项留在文字
- **图的标题是结论。** 如「三天里，7 个纪录被刷新」「认错了，它自己不知道」
- **图在说完那句话之后出现。** 文字先抛判断，图来演示
- **画面都是真实的操作或数据**：真实的按钮路径、真实的榜单数字、真实截图的局部
- **文字很短**：全文 700–1800 字，句子口语化，很少用句号，常见「不妨来试一试」式收尾
- **给读者一句可复制的话**：技术稿常放一段发给 Agent 的提示词，用引用块标出

正文样式：15px，`#4a4a45`，行高 1.9；小标题是 22px 衬线红字 `#cf4436`，上方有分隔线；关键句红色加粗。

## 场景类型

全部 49 张按主画面归类（人工判断，有些图是混合的）：

- 模拟产品界面 + 光标点击：最多，如账单页、弹窗、GitHub 页面
- 终端或 agent 运行：如安装流程、命令执行
- 手机演示：DSH Go 全篇，AGI Bar 小程序
- 数据：条形赛跑、榜单卡、打分条、方格墙
- 流程和原理：流水线分流、扫描比对、投机采样
- 手绘小场景：酒水物流、接啤酒、序列帧吉祥物

8 个模板覆盖前四类的常见形态。最后一类和复杂的产品界面需要按篇定制，这也是原作最费功夫的部分。

## 尚未验证

1. **草稿接口是否完整保留动画。** 实物是从已发布文章看到的，正文里的 `<span leaf>` 和 `<tspan leaf>` 说明内容经过了公众号编辑器，但无法判断作者用接口还是别的方式写入
2. **接口的体积上限。** 官方社区只确认接口与后台限制不一致，超限报 45002，没有给出可靠数字
3. **手机微信内的实际播放。** 已在 Chrome 手机宽度下验证实时播放，也模拟了微信的小写化和 tspan 包裹且渲染一致，但没有在真机微信里跑过

验证方法：向测试账号发一篇小稿，让 `bin/publish.py` 读回核对，再用手机预览。
